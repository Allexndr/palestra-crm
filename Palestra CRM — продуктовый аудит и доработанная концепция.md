# Palestra CRM — продуктовый аудит и доработанная концепция

> Сводный документ поверх: [ТЗ и концепция мультиклубной платформы…](ТЗ%20и%20концепция%20мультиклубной%20платформы%20для%20бойцовских%20клубов%20и%20единоборств.md), [Расширенное ТЗ…](Расширенное%20ТЗ%20мультиклубной%20платформы%20для%20бойцовских%20клубов%20и%20единоборств.md) и дизайн‑системы / FSD.  
> **Назначение:** единая улучшенная стратегия для запуска, продажи и развития продукта.

---

## 1. Синтез идей из исходных материалов

| Источник | Суть |
|----------|------|
| **Концепция / Расширенное ТЗ** | Мультиклубный SaaS: CRM, расписание, посещаемость, биллинг, соцсеть (ленты club/personal/city), лига и геймификация, семейные аккаунты, white‑label и add-ons (локации, аналитика). |
| **Дизайн‑система + FSD** | Токены, mobile-first (bottom nav для учеников, sidebar для админов), JSON‑подобные флоу регистрации клуба, локаций, лиги, приглашений, биллинга участников, ленты, настроек профиля. |
| **Архитектура (доп. документ FSD)** | Next.js / Tailwind, Postgres, multi-tenant `tenant_id` / `club_id`, сущности User, Club, Location, StudentProfile, лиги, посты, достижения. |
| **Реализация демо (Palestra)** | React + Vite, геймификация RPG (ученик = «герой»), роли Admin / Coach / Parent / Student, LocalStorage, лендинг, админка, feed и профили — фокус на вовлечении и retention. |

**Общий продуктовый нарратив:** «Операционная система клуба единоборств» = операционка (лиды, членство, деньги, залы) + мотивация (RPG, лига) + community (лента) + семья (родительский кабинет).

## 2. Аудит: сильные стороны

1. **Чёткое дифференцирование** — соцсеть и лига + RPG там, где у конкурентов в основном расписание и биллинг.
2. **Мультиклубность** — один аккаунт на несколько клубов решает реальную боль учеников и родителей.
3. **Роли** — владелец, тренер, ученик, родитель покрывают B2B и B2C2B одновременно.
4. **Ценовая гипотеза** — база + add-ons (локации, tier по ученикам) согласуется с рыночными паттернами gym/martial arts SaaS.
5. **FSD** — снижает разрыв между продуктом, дизайном и разработкой.
6. **Демо-продукт** — RPG и «живая» старая идея снижать churn через вовлечение.

## 3. Аудит: пробелы, риски, противоречия

| Область | Пробел / риск | Рекомендация |
|---------|----------------|--------------|
| **Стек в документации** | Смешение Next/Postgres (ТЗ) и Vite/LocalStorage (текущий демо). | Явно разделить: *Prototype* vs *Production* roadmap; в мастер-концепции один «целевой» production-стек. |
| **Соцсеть** | Модерация, жалобы, дети, DMCA, публичные vs клубные ленты недостаточно детализированы. | Модель видимости постов, возрастные флаги, роли модераторов, отчёты, опциональное pre-moderation для несовершеннолетних. |
| **RPG-статистика** | «Сила/скорость» без привязки к методике — риск дискредитации у серьёзных клубов. | Разделить: игровые мета-статы (XP, стрики) vs *опциональные* спортивные чек-листы / грейдинг по дисциплине, задаётся клубом. |
| **Платежи** | KZ/СНГ: Stripe не всегда; налоги, чеки, эквайринг. | Roadmap: один локальный провайдер + «инвойсы вручную» для MVP. |
| **Аналитика** | «Расширенная аналитика» без набора core-метрик. | Зафиксировать North Star, когорты, воронка лида, MRR, посещаемость, churn по абонементу. |
| **Безопасность** | Multi-tenant без RLS/политик в ТЗ. | В production: RLS в Postgres или строгий data-access слой + аудит. |
| **Контент-мерч** | Магазин в демо без логистики, остатков, налогов. | MVP: витрина + «заявка/оплата офлайн» или интеграция позже. |

## 4. Улучшенное позиционирование

- **Владелец / сеть:** «Меньше ручного Excel, больше предсказуемой выручки и удержания — одна система на все локации.»
- **Тренер:** «Одна кнопка: кто на занятии, кто рискует отвалиться, что написать родителю.»
- **Родитель:** «Видно расписание, оплату и прогресс без десяти чатов.»
- **Ученик:** «Клуб как игра: уровни и лига — не отдельное приложение, а часть тренировки.»

**One-liner (варианты):**  
*«Palestra — CRM и RPG для клубов единоборств: деньги, расписание и мотивация в одной платформе.»*

## 5. Лендинг: доработанная структура и воронка

### 5.1. Целевой путь

`Трафик → Понимание за 5 сек → Доверие → Сравнение → Демо/триал → Онбординг клуба`

### 5.2. Секции (сверху вниз)

1. **Hero** — H1 = ценность для *клуба* (не «еще одна CRM»), подзаголовок = CRM + мотивация + community, 2 CTA: «Попробовать 14 дней» / «Смотреть демо».
2. **Соцдоказательства** — логотипы клубов, цифры (если есть), короткие цитаты владельцев/тренеров.
3. **Боли → решения** — 3–4 пары: хаос в чатах / лиды / отток / мультилокации.
4. **Как это работает** — 3 шага: зарегистрировал → импорт/приглашения → первая неделя в цифрах.
5. **Модули (табы или якоря)** — CRM и лиды, расписание и залы, родители и оплаты, лента, лига и RPG, аналитика, мерч (если в продукте).
6. **Сравнение** — «vs Excel / vs чистый мессенджер / vs зарубежные CRM без лиги» (честно, без перегиба).
7. **Тарифы** — прозрачно: что в базе, за что add-on (локации, лимит учеников, white-label). Убрать ощущение «скрытых ножей».
8. **FAQ** — дети, данные, отмена, интеграции платежей, экспорт.
9. **Финальный CTA** + форма lead (имя, клуб, контакт) для тех, кто не готов к саморегистрации.

### 5.3. Микро-улучшения

- A/B: заголовок «операционная система» vs «меньше оттока и больше оплат».
- Видео 60–90 сек: тренер отмечает посещаемость → push родителю → ученик видит +XP.
- **SEO:** страницы по дисциплинам/городам (например «CRM для BJJ в …») — отдельный контент-план, не в MVP лендинга v1.

## 6. Внутренняя платформа: доработки по ролям и модулям

### 6.1. Администратор

- **Дашборд:** не только «красиво», а *действия*: неоплаты, лиды «зависли», пустые слоты в расписании, топ оттока.
- **Настройки дисциплин** — шаблоны рангов/поясов per discipline, синхрон с прогрессом ученика.
- **Billing платформы** — отдельно от абонементов клуба: счета, add-ons, пределы.

### 6.2. Тренер

- **Мобильный first:** чек-ин, заметка к уроку, 1-tap «отметил посещаемость → триггер XP/лига».
- **Лента:** публикация от имени клуба/тренера с шаблонами («результаты на турнире»).

### 6.3. Ученик (RPG)

- **Две оси UI:** (A) «Игра» — XP, стрики, бейджи, лига; (B) «Спорт» — ранг, грейд, цели тренера.
- **Согласие:** настройка клуба «включить игровые баффы для возрастной группы X».

### 6.4. Родитель

- **Переключение детей** — как в демо, плюс агрегированные уведомления и «тихие часы».
- **Оплата** — дата списания, чек, возвраты/заморозка — статусы на языке договора.

### 6.5. Соцсеть

- **Минимум для v1:** клубная лента + комменты; межклубная / city — feature-flag.
- **Модерация:** репорты, скрытие, бан, журнал действий, политика для UGC.

### 6.6. Лига

- **Внутриклуб** в MVP; **межклуб** — отдельный этап (юридически и операционно сложнее).
- Правила начисления — хранить как data-driven правила, не только текст.

### 6.7. Магазин (мерч)

- До реальной логистики: «каталог + заказ/оплата вручную» или отложенный модуль.

## 7. Современные тенденции (встроить в roadmap, не все в v1)

| Тренд | Как встроить в Palestra |
|--------|-------------------------|
| **PWA / установка** | Один код для тренеров/родителей на телефоне; критично для чек-ина и пушей. |
| **Умные уведомления** | Триггеры: «3 пропуска подряд», «абонемент 7 дней», «лид не отвечает» — с лимитами antispam. |
| **AI (опционально)** | Краткие summary для владельца: «неделя в клубе»; черновики постов/ответов лиду — с ручным approve. |
| **Creator‑профили тренеров** | Публичная страница тренера с расписанием и CTA «пробная» — усиливает лендинг клуба. |
| **Соответствие и дети** | Минимизация PII в публичных постах, возрастные настройки, согласия родителей. |
| **Интеграции** | Календари (ics), webhooks, позже: WhatsApp Business API, Telegram боты для напоминаний. |

## 8. MVP и границы

**MVP (must-have):**  
регистрация клуба и онбординг · база учеников/лидов · расписание и посещаемость · абонементы/статусы (хотя бы ручные + даты) · родитель/ученик кабинет (read-heavy) · пуш/e-mail уведомления (хотя бы критичные) · **упрощённая** лига и RPG (XP за посещение + ручные ачивки) · безопасный multi-tenant · базовая клубная лента (или даже «новости клуба» без full social, если сроки жмут).

**Post-MVP:** межклубная лига, продвинутый турнирный модуль, тяжёлая аналитика, полноценный мерч, white-label, AI.

**Сознательно не в v1:** полный аналог Instagram, онлайн-судейство турниров, нативные приложения в сторах (если PWA закрывает 80%).

## 9. Roadmap 30 / 60 / 90 дней (ориентир)

| Срок | Фокус |
|------|--------|
| **0–30** | Стабильный «день из жизни клуба»: мастер онбординга, импорт/приглашения, расписание, посещаемость, 1 сценарий оплаты/статуса, дашборд владельца с 5 KPI, PWA-гигиена. |
| **30–60** | Родитель+ребёнок, уведомления, упрощённая лига+RPG, модерация ленты, платёжный провайдер (1 интеграция). |
| **60–90** | Add-ons биллинга платформы, white-label beta, отчёты (выручка, churn, воронка лидов), публичная карточка клуба как мини-site. |

## 10. Бизнес: метрики и гипотезы

**North Star (кандидат):** *активные ученики с ≥1 посещением в неделю на платформе* × удержание клубов.

**Для клуба (GTM-сторис):** снижение no-show, рост conversion лида, рост reactivation.

**Unit economics (гипотезы для валидации):** CAC на клуб, LTV, churn клубов, ARPA, доля клубов с 2+ локациями, attach rate add-ons.

**Каналы:** прямые продажи в локальные клубы, партнёры-федерации, контент «как собрать digital-клуб».

## 11. Согласованность с демо-репозиторием (Palestra)

- **Сохранить уникальное:** RPG, роли, лента, премиальная визуальная подача бренда.
- **Свести с ТЗ:** в README явно: демо = Vite+LocalStorage; **production target** = из раздела FSD/Расширенного ТЗ (Next/Postgres multi-tenant) — чтобы не путать стейкхолдеров.
- **Лендинг демо:** доработать по секциям п.5 настоящего документа при готовности к публичному маркетингу.

## 12. Итог

Концепция **Palestra** уже сочетает редкие для рынка элементы: **клубный SaaS + community + игра + семья**. Чтобы продукт выигрывал на демо и в продажах, недостаёт не идей, а **жёстких границ MVP**, **модерации/приватности**, **согласованного стека**, **честного лендинга под ICP** и **метрик, по которым клуб платит в следующем месяце**. Этот документ — основа для презентации инвестору, партнёру-клубу и приоритизации бэклога.
